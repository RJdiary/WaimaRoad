# 阶段 0（可选）· 用 Codex `build-web-apps` 插件做视觉原型

> 本文件是**可选前置阶段**，不产出小程序代码。它的唯一目的是：在写第一行 WXML 之前，用浏览器把 6 屏视觉跑通、把争议收敛掉。
> 读完 `00-baseline.md` §4 与 `docs/ui_design.html` 再执行本阶段。

---

## 1. 先说清楚这个插件能不能「生成这个小程序」

**不能。结论写在这里，避免后面白花时间：**

| 维度 | `build-web-apps` 插件 | 本项目交付物 |
| --- | --- | --- |
| 目标产物 | 浏览器里的 Web 应用（React / Next.js 为主） | 微信原生小程序（WXML + WXSS + JS） |
| UI 体系 | shadcn/ui + Tailwind 类工具链 | 零 npm、手写组件、CSS 变量 Token |
| 依赖 | npm / 构建步骤 / bundler | 零依赖、无构建（`project.config.json` 直接编译） |
| 验证方式 | 浏览器运行 + 自动化截图/交互 | 微信开发者工具模拟器 + 真机 |
| 组件能力 | DOM / CSS 动画 / 浏览器 API | 原生 `map`、`swiper`、`movable-area`、`wx.*` API |

按官方 `openai/plugins` 仓库，该插件打包的是 `frontend-app-builder`、`frontend-testing-debugging`、`react-best-practices`、`shadcn-best-practices`、`stripe-best-practices`、`supabase-best-practices` 这一组技能——全部面向「浏览器 + React 生态」。

**所以：插件不承担 01—05 的实现，只承担本阶段的「视觉原型」。**
强行让它生成小程序，只会得到一份 React 版 UI，再被翻译两次，最终既慢又走形。

---

## 2. 它在这个项目里到底解决什么

| 问题 | 原型阶段的解法 |
| --- | --- |
| 设计稿是 PDF，看着对、写出来走形 | 先出浏览器版，肉眼对齐一遍再落 WXSS |
| 拼贴头部 / 竖排书法 / 今昔对比滑块这类「靠手感」的版式 | 先在 DOM 里调参数，把数值记下来 |
| 手绘素材还没有 | 原型里生成一套占位（渐变 + 文字 + CSS 图形），顺便确定素材尺寸 |
| 字体缩放（`--fs` 0.9—1.3）会不会撑破版式 | 浏览器里直接改 `--fs` 看崩不崩 |
| 6 屏之间的视觉一致性 | 一次生成 6 屏并排对比 |

**它不解决**：`map` 同层渲染、`wx.getLocation` 授权、分包、自定义 TabBar 拖拽层级、Canvas 海报、微信审核。这些只在小程序里成立。

## 4. 可直接复制的提示词

> 用法：在 Codex 里开启 `build-web-apps` 插件，先贴 `00-baseline.md` §4，再贴下面这段。

```
角色：你是资深 UI 还原工程师。本任务只产出「浏览器可开的静态视觉原型」，不写小程序代码，不改任何色值。

【事实源】
- 产品：埠影寻踪（汕头小公园开埠区·外马路历史文化街区的地方史探索小程序）。
- 设计 Token 与 6 屏版式：docs/ui_design.html（已存在，作为基线，不得重新设计风格）。
- 每屏内容与文案：docs/prd.md 第 4 章。

【产出】
1. prototype/index.html：单文件，双击即可打开，不依赖 npm、不引入任何外链资源（字体、CDN、图标库一律不用）。
2. 内容：把现有 docs/ui_design.html 的 6 屏（探索 / 史料 / 史料详情 / 走街 / 我的 / 登录）重排为「6 屏并排 + 375×780 手机框」，并补齐设计 Token 展示区。
3. 版式必须按 750rpx 设计稿换算：1rpx = 0.5px。左右边距 48rpx=24px、卡间距 24rpx=12px、区块 40rpx=20px、TabBar 112rpx=56px。
4. 图片一律用占位：暖色渐变底 + 建筑名文字；不得出现外部图片链接。
5. 增加一个「字号缩放」控件：改动 --fs（0.9 / 1.0 / 1.15 / 1.3），验证所有屏不溢出、不截断、不重叠。
6. 交互可演示但不必真实：POI 卡出现/收起、对比滑块拖动、TabBar 高亮切换、统计数字滚动。

【约束】
- 不引入 React / Next / Tailwind / shadcn / 任何 npm 包；不用外部字体；不做暗色模式。
- 色值只能来自 18 个 Token（--bg #FCF7EE、--apricot #FFE8C7、--terracotta #D98C75、--amber #F0AD45、--blue #1A91FA …），不得新增或微调。
- 不出现旧版命名（埠藏史库·街绘行图 / heritage / street / mine）、不出现济南地名。
- 文案照抄 docs/prd.md，不改写、不润色、不中英混排。

【完成标志】
- 浏览器打开 6 屏并排，横向无滚动条、无遮挡、无溢出。
- 在 --fs=1.3 时仍不破版。
- 输出一份「实现备注」：把每屏用到的关键数值（宽高、间距、字号、圆角）按 rpx 列成表，供 01/02/03/04 阶段直接抄。
```

## 5. 视觉冻结与交接

原型通过后，只允许做三件事，做完就冻结，进入阶段 01：

1. **回写数值**：把原型里调出来的 rpx 数值写进 `docs/ui_design.html` 的实现标注区（只改样式数值，不改 Token 名与色值）。
2. **确认差异清单**：若原型与 PDF 设计稿不一致，以 PDF 为准，在 `docs/ui_design.html` 记录「设计稿 → 实现」的取值。
3. **落素材清单**：把原型里的占位尺寸抄进 `00-baseline.md` §10 的素材表，作为正式切图规格。

**禁止**：把 `prototype/` 纳入主链路（它是参考物，不是交付物）；把原型里的组件结构直接翻译成小程序（DOM 结构与 WXML 结构不同，翻译会引入层级问题）。

> `prototype/` 建议加入 `.gitignore`；若保留，README 需注明「浏览器原型，非交付物」。

## 6. 反模式（出现即回退）

| 反模式 | 为什么错 |
| --- | --- |
| 让插件「直接生成小程序页面」 | 它只会输出 Web 代码，再人工翻译等于写两遍 |
| 在 `prototype/` 里装 React / shadcn / Tailwind | 交付物零依赖，原型与实现的技术栈差距越大，迁移成本越高 |
| 用浏览器截图代替微信开发者工具验收 | `map`、`swiper`、`movable-area` 的行为在浏览器里不成立 |
| 借机「优化」设计风格 | 设计稿已定，风格漂移会让 01—05 的 Token 全部对不上 |
| 在原型阶段改业务规则或文案 | 规则在 `00-baseline.md` §8 与 `docs/prd.md` 第 5 章，改了就出现两套事实 |
| 把原型当最终验收物给客户 | 客户看的是小程序，不是 HTML |

## 7. 与阶段 01 的衔接

```

        │
        ▼
```

- 阶段 01 的 `app.wxss` 不得「再顺手调一下」色值或字号；要改先改 `00-baseline.md` §4，再改 01。
